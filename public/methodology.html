Transparent methodology

Security decisions need more than a checklist score.

AgentRiskLayer separates declared exposure, control effectiveness and evidence confidence, then adds hosted or local runtime policy decisions, integrity-verified technical observations from an optional local scanner, asset drift evidence and controlled adversarial outcomes from a customer-operated staging runner.

Inherent exposure

Measures data sensitivity, autonomy, high-impact actions, public reach, external content, connected tools and delegation.

Control weakness

Measures identity, authorisation, approvals, input boundaries, validation, memory, egress, monitoring, testing and containment.

Evidence confidence

Distinguishes no evidence, owner claims, documented controls and tested evidence. Unsupported claims increase uncertainty.

Attack paths

Combines multiple conditions into scenarios such as indirect prompt injection leading to privileged tool execution.

Runtime policy enforcement

Evaluates supplied input, output and tool-call metadata against versioned project policy. Hosted evidence excludes raw content; a local gateway is available for customer-contained processing.

Asset drift and remediation

Compares declared agents, models, MCP servers, tools, gateways and vector stores over time, changes the deployment gate for risky drift and tracks owned remediation to verification.

Local technical inspection

Checks tracked files and deployment configuration for secrets, supply-chain risk, MCP/tool scope, container controls, CI/CD permissions and agent-control signals.

Controlled adversarial testing

Exercises a 32-case catalogue across direct, indirect, encoded and multilingual prompt injection, synthetic exfiltration, dry-run tool misuse, SSRF and injection-shaped tool arguments, memory poisoning, tenant isolation, schema enforcement, authority confusion and resource limits. Cases can repeat 1-5 times to measure stability.

Evidence integrity

Inspection and red-team bundles use SHA-256 and Ed25519, one-time upload tokens and replay protection. Source code, raw prompts, target responses, credentials and matched secret values are excluded.

Framework basis

The control library is informed by OWASP guidance for agentic applications and AI agents, the OWASP LLM Top 10, NIST AI RMF 1.0 and the NIST Generative AI Profile.

Written Rules of Engagement

Every staging campaign must be bound to a named target, legal authority basis, named authoriser, emergency stop contact, approved time window, permitted and prohibited actions, synthetic-data attestation, dry-run-tools attestation and explicit confirmation. The server rejects missing, expired, revoked, environment-mismatched or endpoint-mismatched authorisations.

What the assessment is

A structured, explainable self-assessment and remediation planning tool that helps teams identify control gaps and prepare for deeper security work.

What it is not

The hosted Guard API screens only the content and metadata supplied to it and does not execute customer tools. The inspector is static and the red-team runner is controlled and customer-operated. None is an independent penetration test, complete runtime attestation, audit, certification, legal advice or guarantee that a system is secure. Production and destructive testing are intentionally excluded.

Inspection trust model

The signature proves that an accepted inspection or red-team evidence bundle was not changed after local generation. Repeated trials improve stability evidence but do not prove security outside the tested cases and adapter behaviour. It does not prove that the customer scanned every relevant repository, that production matches the scanned material, or that the system was uncompromised. Reports state this boundary prominently.

Scoring

Residual risk combines inherent exposure (38%), control gaps (62%) and an uncertainty penalty where answers lack documented or tested evidence. Scores prioritise action; they are not probabilities of breach.
