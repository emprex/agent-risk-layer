What actually goes wrong

An agent does not need to be malicious to create serious risk.

Ordinary authority, untrusted input and weak enforcement are enough. The important question is whether the boundary survives when the system is challenged.

Untrusted input

The instruction looked legitimate. The authority was not.

A model can be influenced by email, documents, retrieved content or websites. The important control is whether a proposed action still has to pass an authoritative boundary before the side effect occurs.

Watch the controlled example →
Excessive authority

The model does not need to be compromised to cause damage.

Broad permissions can turn an ordinary model error into a filesystem change, customer-data exposure or high-impact business action. Authority has to be visible before risk can be controlled.

Remediation and retest

A remediation is not evidence that the risk is fixed.

The changed system must be assessed against the same failure and reasonable bypass variants. If the retest fails, the finding stays open and the evidence chain continues.
